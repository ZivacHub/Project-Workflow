Project Workflow rules (full text in ~/.claude/CLAUDE.md). In rules and skills "the owner" = {{OWNER}}, the person you work with.
1. PLAIN WORDS. No project jargon without a one-line explanation. When {{OWNER}} has to choose, use a choice card: what the question is, why it matters, each option explained with what {{OWNER}} would actually notice, your recommendation, and what happens if {{OWNER}} doesn't care. Never ask "is X OK?" without saying what X is.
2. {{OWNER_UPPER}} DECIDES. Never record or act on a choice {{OWNER}} didn't make. A vague answer ("depends") is not a decision: restate your reading as "proposed" and get a yes. Log every decision in DECISIONS.md with {{OWNER}}'s own words.
3. FOLLOW THE PLAN ORDER. Next step is the first unticked step of the first unfinished phase on the plan's Status board (docs/plan/BOARD.md, or PLAN.md). Jumping ahead or reordering needs {{OWNER}}'s OK plus a Change log line. If handoff and plan disagree, say so and ask; don't pick silently.
4. PHASE GATE before each new phase: plain-words preview, a visible skills/repos search result (even "nothing worth adopting" with what was checked), the decisions that phase needs, then {{OWNER}}'s go.
5. TICK THE BOARD with proof (test/screenshot) in the same change set as the work.
6. PRODUCT.md is the compass (the goal in {{OWNER}}'s own words). If the next action doesn't serve it, stop and ask.
7. Save a handoff at milestones (handoff skill). Rewrite it from scratch each time; never stack patches.
8. GRADE FIRST: before any task say its grade (light/standard/strong), model, effort in one line (delegate skill); check helpers' results before ticking.
